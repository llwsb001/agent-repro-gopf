# 性能记录

## macOS 本机

本机 macOS ARM64，Zig 0.17.1 `ReleaseFast`，4 个 `kqueue` worker。Go 对照为题目引用的 308 行原版 `a80116d`，用 Go 1.27.4 构建。两者串行共用仓库根目录的 `bench_backend.go` 和 `bench_load.go`，端口由本次运行分配。

### 短连接

先以 50 并发请求 2,000 次预热，再以 100 并发请求 10,000 次，每种实现跑三轮。各指标取三轮中位数。

| 实现 | 三轮 rps | 中位 rps | p50 | p99 |
|---|---|---:|---:|---:|
| Zig | 13,588 / 12,356 / 12,195 | 12,356 | 7.50 ms | 13.05 ms |
| Go | 13,607 / 12,207 / 13,604 | 13,604 | 7.25 ms | 15.97 ms |

Zig 全程未报告拒绝连接。接入线程向 worker 移交连接，worker 负责非阻塞拨号和转发。这次没有分离这些步骤的成本。

### 1 MiB 响应

`/big`，4 并发，100 请求，按每个响应的 1 MiB 数据折算吞吐。

| 实现 | 吞吐 | p99 |
|---|---:|---:|
| Zig | 1,414 MiB/s | 5.08 ms |
| Go | 648 MiB/s | 81.45 ms |

大包各跑一轮，记录本次观测。

### 10,000 条在线连接

另用回环 TCP 保持 10,000 条代理连接同时打开，前端用 IPv4，后端用 IPv6。建立完毕后检查代理状态，再逐条连接做短数据的双向字节校验。保持所有连接打开时发送 `SIGTERM`，代理以状态码 0 退出。

- 建连 **10,000 / 10,000**，拒绝 **0**，耗时 1.43 秒。
- **10,000 条**均通过前后两个方向的数据校验。
- 连接空闲时代理有 **5 个 OS 线程**，进程 RSS 为 **4.5 MiB**。内核 socket 缓冲另计。

这是在线连接容量验证。短连接吞吐与延迟见上面的独立压测。

## Linux `gz` 复测

通过 `sz` 跳板连接 `gz`。环境为 x86_64、2 个逻辑 CPU、Linux 3.10.0。Zig 0.17.1 `ReleaseFast` 目标为 `x86_64-linux.3.10-musl`。Go 原版仍为 `a80116d`，用 Go 1.27.4 构建。后端、代理和压测器都在同机回环运行，各代理串行测试。短连接按前述方式预热，每种实现的大包也跑了三轮。各指标独立取三轮中位数。

| 实现 | 短连接三轮 rps | 中位 rps | p50 | p99 | 1 MiB 三轮 MiB/s | 1 MiB 中位 MiB/s |
|---|---|---:|---:|---:|---|---:|
| Zig，1 worker | 12,291 / 12,371 / 12,255 | 12,291 | 7.92 ms | 14.24 ms | 418 / 454 / 455 | 454 |
| Zig，2 workers | 13,661 / 12,913 / 13,087 | 13,087 | 7.16 ms | 16.30 ms | 428 / 426 / 432 | 428 |
| Go 原版 | 10,892 / 10,859 / 11,276 | 10,892 | 8.56 ms | 17.31 ms | 435 / 416 / 417 | 417 |

2 个 worker 的短连接吞吐比单 worker 高 6.5%，比 Go 原版高 20.2%。单 worker 的短连接 p99 更低，4 并发大包吞吐也略高。

2 个 worker 在 0.74 秒内建立 10,000 条代理连接，零拒绝。保持连接全部在线，分批发送带编号的短数据，所有连接两个方向的字节均正确。空闲时代理有 3 个 OS 线程，进程 RSS 为 2.30 MiB，内核 socket 缓冲另计。10,000 条连接仍在线时发送 `SIGTERM`，代理退出码为 0。FD 软上限 32,768 仅适用于本次测试进程。

Linux 原生测试 8/8 通过。第一次跑背压用例时，反向数据已经送达，随后的排空仍受夹具 4 KiB 接收窗口限制并超时。夹具现于反向校验后恢复接收缓冲，再验证积压数据完整送达。相同测试在 macOS 原生也 8/8 通过。

### 10,000 条连接同时传输

仍在 `gz`，2 个 worker。前端走 IPv4 回环，后端走 IPv6 回环。每轮先预建 10,000 条连接，确认代理状态为 `active=10000` 且打开了 20,012 个 FD，再统一放行每条连接上的一个 HTTP 请求。预建约 2.84–2.86 秒，单独记录。延迟从统一放行计到响应体读完。吞吐按成功响应数和响应体字节数计算，p99 取成功样本。

临时 Go 后端在启动时分配小包和大包响应体，并在各请求间复用。原压测后端逐请求转换大包响应体，首次运行触发了压测脚本的宿主机剩余内存保护。以下六轮均使用复用响应体的临时后端。

| 负载 | 三轮成功数 | 三轮吞吐（rps） | 中位吞吐 | 三轮 p99 | 中位 p99 |
|---|---|---|---|---|---:|
| 396 B | 10,000 / 10,000 / 10,000 | 16,298 / 15,557 / 16,154 | 16,154 rps，6.10 MiB/s | 578 / 635 / 535 ms | 578 ms |
| 1 MiB | 10,000 / 9,991 / 10,000 | 719 / 714 / 712 | 714 rps，714.30 MiB/s | 13.90 / 13.98 / 13.81 s | 13.90 s |

大包第二轮有 9 个响应在完整响应体到达前遇到 EOF。三轮接入拒绝数均为 0。另用带代理 I/O 和后端短写日志的临时诊断版本跑了两轮大包，两轮均为 10,000/10,000。提前 EOF 未复现，原因未确定。

#### Go 原版对照

在 `gz` 用相同的临时后端、压测客户端和预建连接流程测 Go 原版 `a80116d`。两种实现的请求截止时间均为 180 秒。吞吐分母为发压到整轮结束的时间，p99 取完整响应的样本。

| 负载 | 三轮成功数 | 三轮吞吐（rps） | 中位吞吐 | 三轮 p99 | 中位 p99 |
|---|---|---|---|---|---:|
| 396 B | 10,000 / 10,000 / 10,000 | 15,303 / 15,653 / 16,159 | 15,653 rps，5.91 MiB/s | 586 / 549 / 570 ms | 570 ms |
| 1 MiB | 9,894 / 9,905 / 10,000 | 54.94 / 55.00 / 799.84 | 55.00 rps，55.00 MiB/s | 13.48 / 13.06 / 12.34 s | 13.06 s |

Go 大包前两轮等到请求截止，分别耗时 180.10 和 180.10 秒，观察到连接重置、提前 EOF 和超时。第三轮 12.50 秒完整传完 10,000 个响应，吞吐 799.84 MiB/s。两轮的超时等待拉低了整轮吞吐，成功响应的 p99 仍是 13 秒量级。

预建完成时 Go 代理有 60,008 个 FD，Zig 有 20,012 个。运行中在 Go 进程观察到 40,000 个管道 FD，与两条方向分别走 Linux `splice` 的管道分配一致。

#### Go 大包卡顿排查

在 `gz` 继续测同一个 Go 原版、Go 1.27.4 和 Linux 3.10。每轮预建 10,000 条连接，同时请求 1 MiB 响应。复测用 45 秒客户端截止时间捕捉卡顿。先用能记录请求阶段的临时夹具做对照，再沿用上一节的预建连接客户端、复用响应体的后端和三轮小包预热，复跑大包。各变体均在临时目录构建。

| 变体 | 大包复跑的失败数 |
|---|---|
| 原版 | 0 / 0 / 16 / 0 / 0 / 0 |
| 只屏蔽 `io.Copy` 的 `WriterTo` 和 `ReaderFrom` 快路径 | 0 / 0 / 0 / 0，管道 FD 从 40,000 降为 0 |
| 保留 `splice`，只将反向 `CloseRead` 改为 `CloseWrite` | 0 / 0 |

复现的一轮在发压后第 22 秒和第 32 秒，都有 13 个客户端 TCP 连接保持 `ESTABLISHED`，客户端和对应代理前端方向的发送、接收队列为空。同时有 11 个代理上游连接为 `CLOSE_WAIT`，接收队列仍有数据。进程栈采样看到了 `internal/poll.splicePump` 和 `spliceDrain`。客户端失败日志直接报读响应体超时，整轮在 45.03 秒结束。前一组 180 秒来自压测客户端的请求截止时间。

现场证据指向原版走 `splice` 的回程转发路径。仅关闭快路径的对照四轮通过。仅改半关闭的两轮也通过，原版也有通过的轮次。现场未定位到具体的内核调用或 Go 的就绪等待机制。额外两次准备读取管道积压的原版复跑均正常完成。
