# gopf-zig 性能测试报告

## 环境与方法

- 机器：本机 Linux x86_64，`nproc` = 4。
- 被测程序：`zig build -Doptimize=ReleaseFast` 产物 `zig-out/bin/gopf`（**优化级别 ReleaseFast**）。
- 后端：`../bench_backend -addr 127.0.0.1:18091`（`/` 返回 396 B，`/big` 返回 1 MiB）。
- 压测器：`../bench_load`（每请求新建 TCP 连接，`Connection: close`）。
- 代理监听 `127.0.0.1:12481`，配置 `settings.conf` 指向 `127.0.0.1:18091`（weight 100）。
- 流程：先 `-conns 50 -reqs 2000` 预热，再连跑 3 次 `-conns 100 -reqs 10000` 取中位；大包 `-path /big -conns 4 -reqs 100` 跑 3 次取中位。
- 代理日志（每连接一条 Accepted）重定向到文件，与 Go 原版行为一致。

## 差距来源分析

**vs Go 原版（+12% rps，p50 -9%，p99 -32%）：**

1. **每连接执行实体更少**：Go 每连接起 3 个 goroutine（handleConn + 两个 io.Copy 方向），靠 runtime 调度与 channel/WaitGroup 协调；本实现每连接只起 **1 个 OS 线程**，用一次 `poll(2)` 同时照看两个方向，省掉一半转发实体的创建/调度/同步开销。
2. **无 GC、无堆分配热路径**：转发缓冲区（2×32 KiB）直接放在连接线程栈上，配置选择只在锁内拷贝一个地址字符串；Go 的 io.Copy 有缓冲分配与 GC 压力。
3. **尾延迟更稳**：没有 GC STW 与 goroutine 抢占带来的抖动，p99 从 13 ms 降到 ~8.8 ms。
4. 两者都对每连接打日志、都开 TCP_NODELAY（Go 默认开，本实现显式开），这部分开销相当。

**vs 直连后端（17.6k vs 31.8k，约 1.8×）：**

这是用户态 L4 代理的固有成本，压测又是**每请求一条新连接**的最坏模式：

1. 每个请求多一跳：代理要 `accept` → 起线程 → `getaddrinfo`+`connect` 后端 → 两个方向各多一次 read/write 系统调用 → 两次 close；字节在内核里多拷贝一次。
2. 每连接一次线程创建/销毁（~1 MiB 栈的 mmap/munmap）与一次后端拨号，短连接场景下这些固定成本占比很高。
3. poll 唤醒与线程调度引入额外延迟（p50 2.69→5.46 ms）。
4. 大包场景代理吞吐为直连的 ~74%（596 vs 809 MB/s），说明纯数据转发路径效率尚可，差距主要来自每连接固定成本而非拷贝带宽。

若改用 epoll 事件循环 + 连接池/keep-alive 复用，可进一步缩小与直连的差距，但那会偏离 Go 原版"每连接独立转发、连接级生命周期"的语义，故未采用。

## 复现命令

```bash
zig build -Doptimize=ReleaseFast
../bench_backend -addr 127.0.0.1:18091 &
./zig-out/bin/gopf -listen 127.0.0.1:12481 settings.conf 2>proxy.log &
../bench_load -addr 127.0.0.1:12481 -conns 50 -reqs 2000      # 预热
../bench_load -addr 127.0.0.1:12481 -conns 100 -reqs 10000    # ×3
../bench_load -addr 127.0.0.1:12481 -path /big -conns 4 -reqs 100  # ×3
```

## 独立复核（验收方，2026-11-18）

上面的表格是实现方自测数据。提 PR 前由验收方用同一套 `bench_backend` / `bench_load` 重跑（ReleaseFast，同端口，先预热 50×2000）：

| 场景 | 三轮 rps | 中位 rps | 中位 p50 | 中位 p99 |
|---|---|---|---|---|
| gopf-zig | 12993 / 12892 / 13517 | **12993** | 7.38 ms | 12.30 ms |
| Go 原版（同批复测） | 14406 / 14709 / 13503 | **14406** | 6.58 ms | 14.18 ms |

单独只跑代理与后端复测，Zig 中位 **13359 rps**（12717 / 13359 / 14264），结论一致：本实现约为 Go 原版的 **0.90–0.93×**，并非自测表里的 +12%。差异来自共享机的负载波动与自测时的进程环境，引用性能时应以复核数字为准。

1 MiB 大包复核：Zig 578 / 481 / 609，中位 **578 rps ≈ 606 MB/s**；Go 605 rps ≈ 634 MB/s。大包场景两者接近，差在每连接固定开销。

功能验收（验收方独立执行，不采信自述）：`zig build test` 17/17 通过；外部真实 TCP 用例 **10/10**（转发+半关闭、后端主动关闭、加权、SIGHUP 换后端、reload 失败保留旧配置、HTTP 型无半关闭请求/响应、1 MiB sha256、SIGUSR1、100 并发、SIGTERM exit 0）；`curl http://127.0.0.1:12481/` → 200 / 396 字节 / 1.4 ms。
