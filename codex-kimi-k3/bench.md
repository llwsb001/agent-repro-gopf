# 性能测试

被测对象：本目录的 Zig 0.17 实现，`zig build -Doptimize=ReleaseFast`。

## 环境

- 4 vCPU（Xeon 8457C），共享云主机，测试期间 loadavg ≈ 1.3–1.7（存在邻居噪声）。
- Zig 0.17.0；Go 基线由 [RaindyRoye/gopf](https://github.com/RaindyRoye/gopf) 源码用本机 go1.23 构建（`CGO_ENABLED=0`，无优化级别差异）。
- 压测工具：仓库根目录 `bench_backend.go` / `bench_load.go`，与其他 Agent 共用，口径一致。
  - `bench_backend`：`/` 返回 396 字节，`/big` 返回 1 MiB，写完即关连接。
  - `bench_load`：每请求新建 TCP 连接、发 `GET`、读到 EOF、关闭；报告 rps / mean / p50 / p99。
- 端口：代理 12481，Go 基线 12482，后端 18091。

## 方法

按 `task.md` 口径：先 `-conns 50 -reqs 2000` 预热，再连跑 3 次
`-conns 100 -reqs 10000` 取中位；大包用 `-path /big -conns 4 -reqs 100`。

```bash
./bench_backend -addr 127.0.0.1:18091 &
./bench_load -addr 127.0.0.1:12481 -conns 50 -reqs 2000
./bench_load -addr 127.0.0.1:12481 -conns 100 -reqs 10000   # ×3
./bench_load -addr 127.0.0.1:12482 -conns 100 -reqs 10000   # ×3, Go 基线
./bench_load -addr 127.0.0.1:12481 -path /big -conns 4 -reqs 100
```

## 结果：396 字节响应，100 并发

| 实现 | 三轮 rps | 中位 rps | 中位 p50 | 中位 p99 |
|---|---|---|---|---|
| Zig 0.17（ReleaseFast） | 15835 / 17141 / 15826 | **15835** | **5.86 ms** | **14.28 ms** |
| Go 原版（本机复测） | 14322 / 14946 / 14530 | 14530 | 6.36 ms | 15.57 ms |

- 相对 Go 原版：rps **1.09×**，p50 低约 8%，p99 低约 8%。
- `task.md` 给出的历史基线是 15.7k rps / p50 6.0 ms / p99 13 ms；本机复测 Go 只有 14.5k，说明这台共享机当前比出基线时更吵。Zig 的 15.8k 落在历史基线与本机复测之间，差距主要来自机器噪声而非实现。
- 直连后端（绕开代理）历史值 30.9k rps，代理路径约为其一半：每请求多两次 TCP 建连/关闭与两段拷贝，短连接场景下这部分无法摊薄。

## 结果：1 MiB 响应，4 并发

| 实现 | 三轮 rps | 中位 rps | 中位 p50 | 中位 p99 | 吞吐 |
|---|---|---|---|---|---|
| Zig 0.17（ReleaseFast） | 544 / 552 / 569 | **552** | 6.76 ms | 12.55 ms | **≈579 MB/s** |
| Go 原版 | 555 / 546 / 549 | 549 | 6.82 ms | 12.18 ms | ≈576 MB/s |

吞吐按 `rps × 1 MiB` 折算（1 MiB = 1.048576 MB）。大包场景两者基本持平
（差值在噪声内），瓶颈从每连接调度转移到内存拷贝与 loopback 带宽。

## 差距来源

1. **每连接一个执行单元**：Go 是 goroutine（用户态调度、栈按需增长）；本实现用 `std.Io.concurrent`，每连接起一个线程。100 并发即 100 个 OS 线程，创建/唤醒成本高于 goroutine，这是 396 字节短连接场景的主要开销。
2. **两段用户态拷贝**：代理对每个方向各一次 read + write，Go 版相同；区别在于本实现每 16 KiB 分块 flush 一次（为了不让请求/响应憋在缓冲区），小块响应会多一次 write 系统调用。
3. **短连接占主导**：每个请求都要 accept + connect + 两次 shutdown + close，代理只做透传，无法像长连接那样摊薄握手成本。
4. **共享机噪声**：4 vCPU 上同时跑后端、压测器和两个代理，loadavg 1.3–1.7；三轮之间的 ±8% 波动即可解释部分差异，因此结论只看中位数与量级。

## 复现注意事项

- `bench_load` 的客户端**不半关闭**写端（发完请求就等响应）。因此代理必须在读到数据后立即 flush，不能攒到 EOF——这是本实现验收阶段修掉的一个真实缺陷，详见 `IMPL-NOTES.md`。
- 跑之前确认 12481 / 12482 / 18091 没有残留进程，否则 rps 会明显偏低。
