# Zig gopf

Zig 0.17 重写的四层 TCP 负载均衡器。只用 Zig 标准库和 Linux/POSIX 系统调用，
没有第三方依赖，也不调用 Go 参考实现。

## 构建与测试

```bash
/home/user/.local/bin/zig build test
/home/user/.local/bin/zig build -Doptimize=ReleaseFast
```

可执行文件位于 `zig-out/bin/gopf`。

`zig build test` 同时运行两组测试：

- 模块单元测试：配置解析/校验、空 hosts、全零权重、负权重、非法地址、
  固定种子下 10 万次加权选择。
- 集成测试：加载配置后选择集切换、失败重载保留旧配置、真实 TCP 回显代理、
  半关闭传播、1 MiB 以上大包逐字节一致性。

## 运行

本机这一轮的约定监听端口是 `127.0.0.1:12482`（任务书默认示例为 `:1248`）：

```bash
./zig-out/bin/gopf -listen 127.0.0.1:12482 settings.conf
```

配置格式：

```json
{
  "hosts": [
    { "addr": "127.0.0.1:18091", "weight": 100 }
  ]
}
```

`addr` 必须是合法的 `host:port`（IPv6 使用 `[::1]:port`）；`weight` 不能为负。
空 hosts 或权重和为 0 的配置可以加载，但没有可用后端，新连接会被直接关闭。

信号：

- `SIGHUP`：重新读取并校验配置文件；失败时保留旧配置并记录错误。
- `SIGUSR1`：输出活跃连接数、累计连接数和当前配置摘要。
- `SIGTERM` / `SIGINT`：停止接受新连接并退出。

## 设计取舍

**线程模型。** 主线程用 `poll` 同时等待监听套接字和信号自管道。每个客户端连接
由一个分离的工作线程处理，工作线程再启动一个拷贝线程负责反方向数据，因此一条
活跃连接通常占用两个内核线程。这样直接对应参考实现的“每连接一个 goroutine +
双向阻塞拷贝”，语义简单、半关闭处理直接，但连接 churn 高时线程创建成本明显高于
Go 的用户态 goroutine 和 netpoller。后续若追求吞吐，可改成固定 worker pool /
事件循环，由单线程用 `poll` 同时驱动两个方向。

**连接和半关闭。** 接受连接后立即做加权随机选择并拨号，拨号是非阻塞 `connect`
加 5 秒 `poll` 超时，成功后恢复阻塞模式。两个方向各自使用 16 KiB 栈缓冲区拷贝；
任一侧读到 EOF 或出错，都对另一侧执行 `shutdown(WR)`，两个方向都结束后才关闭
整条连接。客户端和后端套接字都设置 `SO_KEEPALIVE`，`TCP_KEEPIDLE` 与
`TCP_KEEPINTVL` 为 60 秒。

**配置快照。** 配置解析产生不可变 `Config`，当前快照以原子指针发布。正常连接只做
一次原子读取，不在热路径持锁；重载先完整解析和校验，成功后才交换指针。旧快照
放入 retired 列表，在进程/测试结束时统一释放，避免连接线程持有快照时被重载线程
释放。配置量很小且重载频率低，这是用少量常驻内存换取无锁读取。

**内存分配。** 启动和重载时的配置对象走通用分配器；每条连接不分配堆内存，两个
16 KiB 拷贝缓冲区位于线程栈上。工作线程栈 256 KiB、拷贝线程栈 64 KiB，远小于
Zig 默认 16 MiB，以降低连接 churn 时的栈预留开销。

**信号。** 信号处理器只做异步信号安全的单字节 `write` 到自管道；主循环读取管道
后执行配置重载、状态打印或停止流程，避免在信号上下文里加锁、分配或格式化输出。
